# 完成状态

`done` 是独立的 JSON 布尔字段，比在 `notes` 写“✅ 已完成”更容易准确筛选，也不会把执行细节和状态混在一起。脚本不会解析或迁移备注中的旧完成标记。

添加时默认 `false`；只有用户明确表示已完成或要求标记时才设为 `true`。先通过 `list` 定位唯一完整 ID，再用 `update` 的 `changes.done` 修改；取消完成用 `false`。不会因开始或结束时间过去而自动完成，日期精度（时间未定）的事项同样支持完成状态。数字和字符串不能代替布尔值。

文件版本保持 1。旧文件可以缺少 `done`；`read_events` 校验后在返回的每项中补 `done:false`，读取本身不改写文件。下一次成功写入会把归一化后的字段保存到磁盘，这是单向归一化；无需单独迁移文件。

`list`、`summary` 的 `status` 可为 `all`（默认）、`pending` 或 `done`，按布尔值筛选，未知值报错。展示方式如下：

| 入口 | 已完成事项 |
| --- | --- |
| `summary` | 保留原行，在标题前加 ✅，如 `• 09:00  ✅ 精读论文` 或 `• 时间未定  ✅ 健身`；备注行与排序不变 |
| 卡片 | 作为当天记录保留全部事项；时间前加 `✓ `，标题加删除线，降低透明度；分页与转义行为不变 |
| `list` | 返回 `done:true` 或 `done:false`，不修改标题或备注 |

调用规则见 [SKILL.md](../SKILL.md)，CLI 示例见 [README.md](../README.md)。
